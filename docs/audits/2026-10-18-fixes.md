# Audit fixes - 18 October 2026

The
[17 October audit](2026-10-17.md) remains the historical baseline; its findings
are not rewritten as if these changes existed during that audit.

The two audited security counterexamples are blocked. The eight reliability
findings have implementation changes below; R4's protection explicitly covers
cooperating writers. This is remediation evidence, not a claim that the entire
application is free of security flaws. No user session was cleared and no model
loading settings were changed.

## Additional reliability and maintenance changes

- Stream through a bounded 128-item queue, showing the first delta immediately
  and rendering subsequent Markdown at a 50 ms cadence plus final flush. Reject late callbacks from a
  completed interaction. A 1,000-delta regression checks exact retained contents
  with fewer than 50 render calls; this is not a comparative throughput benchmark.
- Suppress programmatic model-picker change events during catalog refresh, so
  refresh cannot clear the selected model's context or response statistics.
  Reconcile the visible selection before Send, including a still-queued change
  event; tests wait for actual selection state before directly calling runtime.
- Resolve Git/ripgrep from absolute PATH entries outside the workspace; avoid
  Windows' implicit current-directory executable search and batch-file shells.
- Validate positive, finite configuration limits at construction. Reject
  unsupported security relaxations and bypassing proposal confirmation.
- Maintain `changes.md` and `AGENTS.md` before reporting project work complete.
  Historical audit evidence remains separate from implemented changes.
- Add hash-pinned runtime/development wheel lists and Windows/Linux Python 3.12
  CI. CI action references are pinned to verified upstream commits. The CI
  workflow is configured locally; no GitHub run has been executed in this task.

## Dependency remediation

Updated this project's virtual environment from `pip==25.0.1` to `26.2.1` and
`pytest==8.4.2` to `9.1.1`; updated the development requirements accordingly.
Pinned build tools are `setuptools==84.0.0` and `wheel==0.48.0`.
The runtime SDK/model/UI dependencies retain their previously installed versions.

The new [dependency evidence](2026-10-18-dependencies.json) records a live OSV
query of **34 installed packages, with zero matched packages/advisory IDs**.
That includes the build tools. The original seven tooling matches are historical;
do not count them as seven exploitable application flaws. Absence of a known
version match is not proof that a package has no vulnerabilities.

Reproduce the scan with:

```powershell
.\.venv\Scripts\python.exe scripts/dependency_audit.py --output temp/dependency-audit.json
```

The script sends package identifiers/versions only and fails on query errors.
Wheel hashes in `requirements/runtime.lock` and `requirements/dev.lock` come
from PyPI release metadata. Hash enforcement prevents unnoticed artifact changes
after review; it does not independently establish that an upstream release is
trustworthy. See [pip's installation guidance](https://pip.pypa.io/en/stable/topics/secure-installs/)
and [the OSV API](https://google.github.io/osv.dev/api/).

## Remaining boundaries and proposed work

- **External file races:** portable atomic replacement is not a compare-and-swap
  against unrelated editors or hostile filesystem changes. The final comparison
  and replacement remain separate OS operations. Cooperative writers are locked.
  Stronger protection needs a platform-specific filesystem design and additional
  validation; this report does not claim that boundary is solved.
- **Cancellation:** completed Git/file side effects are not rolled back. Blocking
  network/provider workers may remain until their socket call returns; at most
  one outstanding call per client/provider is allowed. Child supervision is a
  cleanup mechanism for trusted programs, not an OS security sandbox.
- **Durability:** reset/append recovery targets application crashes and injected
  I/O failures. No universal power-loss/disk-failure guarantee is claimed. Clear
  is not secure erasure; failed post-commit cleanup can temporarily retain an old
  directory until a later recovery access succeeds.
- **Scale:** journal compaction/retention, transcript pagination, exact tokenizer
  integration, cache freshness monitoring, repository indexes/RAG, and measured
  comparisons against other assistants remain proposed work. They were not
  implemented or established by these correctness regressions.
- **Validation:** compilation does not establish generated-code correctness.
  Live model behavior and Linux CI remain unverified in this environment.
